# 스펙 01 — 성남 자유수영 시간표 (+ 매일 자동 점검)

> 기준 커밋 `d30cd8c` (2026-09-28). 개요: [스펙-00-개요.md](스펙-00-개요.md)
> 새 수영장 추가 절차는 [지역-추가-플레이북.md](지역-추가-플레이북.md)가 담당한다. 이 문서는 "지금 어떻게 동작하는가"를 정의한다.

## 1. 목적

성남 공공 수영장 11곳의 **오늘·내일 자유수영 시간과 휴관 여부**를 한 화면에서 보여준다.
공식 사이트는 시설마다 따로 있고 휴장 정보가 공지 첨부(PDF·HWP·이미지) 안에 숨어 있어서, 이 사이트가 모아서 계산해 준다.
데이터가 틀어지지 않도록 **매일 밤 공식 사이트를 자동 점검**해 운영자에게 텔레그램으로 알린다.

### 성공 기준
- 방문자가 첫 화면에서 "지금 갈 수 있는 곳"을 바로 안다(운영 중인 곳이 맨 위).
- 휴관일(정기·공휴일·임시·장기 미운영)이 틀리지 않는다.
- 공식 사이트나 공지에 변경이 생기면 **다음 날 밤 전에** 운영자가 안다.

### 범위 밖
- 강습 정보(→ 스펙-03), 정원·혼잡도, 예약, 위치 지도, 성남 외 지역(한강 제외).

## 3. 데이터 모델 (`index.html` 의 `POOLS`)

필수·선택 필드 정의는 플레이북 §3에 있고, 여기서는 **동작에 영향을 주는 필드**만 규정한다.

| 필드 | 형식 | 의미 |
|------|------|------|
| `closedWeeks` | `[n,…]` | 매월 n번째 **일요일** 정기휴관. 일요일이 아닌 날엔 적용 안 됨 |
| `closedOnHoliday` | `'all'` / `'lunar'` / 없음 | `all`=모든 법정공휴일 휴관, `lunar`=설·추석 연휴만 휴장(그 외 공휴일은 일요일 시간표로 운영), 없음=공휴일도 운영 |
| `weekdaySlots` / `saturdaySlots` / `sundaySlots` | 슬롯 배열 또는 `{summer, winter}` | 계절제면 3~10월=summer, 11~2월=winter |
| 슬롯 | `{time:'HH:MM~HH:MM', dur, days?, note?}` | `days`(1=월…5=금)는 평일에만 필터로 적용. **평일** 슬롯의 `note`에 "수심"이 들어가면 목록 메타에 "수심 2m" 표시(note 문구 자체는 화면에 안 나옴) |
| `weekdayPrice` / `weekendPrice` | `{adult, teen, child}` 또는 `null` | 주말·공휴일은 weekend 요금 |
| `priceNote` | 문자열 | 요금이 null이면 요금 대신 이 문구, 요금이 있으면 "※" 보조 문구 |
| `note` | 문자열 | 펼침 시 "※" 보조 문구 |
| `feature` | 문자열/null | 목록 메타 뱃지(50m 풀, 유스센터 등) |
| `startsOn` | `'YYYY-MM-DD'` | 이 날 전에는 "존재하지 않음"(미운영) |
| `notOperating` | `[{from,to,label?}]` | **장기** 휴장. 목록에 "미운영", 달력 색 계산에서 제외 |
| `extraClosedDates` / `extraClosedRanges` | `['YYYY-MM-DD']` / `[[from,to]]` | **단기** 임시휴장. 달력 색 계산에 포함 |
| `specialSchedules` | `[{from, to?, weekdaySlots?, saturdaySlots?, sundaySlots?, weekdayPrice?, weekendPrice?, note?}]` | 기간 한정 시간표·요금. 적은 필드만 덮어씀. `to` 생략=종료일 미정 |
| `holidayVerified` | 문자열 | 기록용(화면 표시 안 함) |

### 공휴일 데이터
- `HOLIDAYS`: 법정공휴일(대체공휴일 포함) 날짜 집합. 현재 2025~2027년. 2027년부터 노동절(5/1)·제헌절(7/17)과 그 대체공휴일 포함.
- `LUNAR_HOLIDAYS`: 설·추석 연휴 날짜(2026~2027년). 설·추석 **대체공휴일은 넣지 않는다**(공사 수영장 휴장 여부 미확인 → 일요일 시간표로 운영).
- 대체공휴일 규칙과 과거 사고(2026-09-28 오입력)는 플레이북 §4.

## 4. 날짜별 계산 규칙 (핵심 로직)

이 함수들은 화면과 공지 감시 스크립트(`site-model.js`)가 **같은 코드를 공유**한다. 드리프트가 없도록 `site-model.js`가 `index.html`의 `const POOLS = [` ~ `const POOL_SHORT`, `const HOLIDAYS` ~ `function mins(` 구간을 잘라 그대로 실행한다. **이 두 구간의 경계 표식을 바꾸면 점검이 깨진다.**

### 4.1 휴관 판정 `isClosedDay(pool, date)` — 위에서부터 먼저 걸리는 것
1. `startsOn` 이전 → 휴관(표시는 "미운영")
2. `notOperating` 기간 → 휴관(표시는 "미운영")
3. `extraClosedDates/Ranges` → 휴관(임시휴장)
4. `closedOnHoliday:'all'` 이고 `HOLIDAYS`에 있음 → 휴관
5. `closedOnHoliday:'lunar'` 이고 `LUNAR_HOLIDAYS`에 있음 → 휴관
6. 일요일이고 그 달 n번째 일요일이 `closedWeeks`에 있음 → 휴관
7. 그 외 → 운영

### 4.2 휴관 사유 `closedReason(pool, date, full)` — 같은 순서
| 조건 | 문구 |
|------|------|
| 개장 전 | `M.D부터 시범운영 예정` |
| 미운영 | `label` 또는 `M/D-M/D 임시 휴장` |
| 임시휴장 | `임시휴장` |
| 공휴일(all) | `공휴일 휴관` |
| 설·추석(lunar) | `설·추석 연휴 휴장` |
| 정기 | full=true: `매월 1·3번째 일요일 정기휴관` / false: `정기휴관` |

### 4.3 시간표 `slotsFor(pool, date)`
- 우선순위: **공휴일 → 일요일 시간표**(토요일 공휴일 포함) > 토 > 일 > 평일.
- 그날 해당하는 `specialSchedules`가 그 요일 키를 갖고 있으면 그것으로 대체.
- `{summer, winter}`면 계절로 고름.
- 평일이면 `days`가 있는 슬롯은 그 요일일 때만 남김.
- 결과가 빈 배열이면 그날은 휴관으로 표시(§4.4).

### 4.4 상태 `poolState(pool, date, isToday)`
| 상태 | 조건 | 우측 표시 |
|------|------|-----------|
| `open` (운영 중) | 오늘, 현재 시각이 어떤 슬롯의 [시작, 끝) 안 | "현재 운영중" + 그 슬롯 시작 시각 |
| `open` (다음) | 오늘, 아직 시작 안 한 슬롯 있음 / 또는 오늘이 아닌 날 | "다음 타임" + 시작 시각 (오늘이 아니면 첫 슬롯) |
| `ended` | 오늘, 모든 슬롯이 지남 | "오늘 종료" |
| `closed` | 휴관 또는 슬롯 없음 | "미운영"(개장 전·미운영) / "휴관" |

- 시각 기준은 **방문자 기기의 로컬 시각**(KST 강제 아님).
- 요금 `priceFor`: 토·일·공휴일=weekendPrice, 그 외 weekdayPrice. 특별 운영 기간이면 그 요금 우선.

## 5. 화면 스펙

### 5.1 레이아웃 (위→아래)
1. **히어로**: 배경 사진, "성남, 오늘의 자유수영". 한강 시즌이면 우상단에 한강 진입 버튼(→ 스펙-02).
2. **탭 바**(스크롤 시 상단 고정): `오늘 (M.D 요일)` · `내일 (M.D 요일)` · `N월 전체보기`(N=이번 달).
3. **본문**: 오늘/내일 = 수영장 목록, 전체보기 = 달력 + 타임라인.
4. **푸터**: 시설 수·출처(공사/유스센터/분당올림픽 링크)·"스케줄은 변경될 수 있으니 각 센터 홈페이지를 확인" 문구 + 피드백 버튼.

### 5.2 오늘/내일 목록
- 정렬: 운영(open) → 종료(ended) → 휴관(closed), 같은 그룹 안에서는 `BASE_ORDER`.
- 행: 상태 점(초록=운영, 회색=종료, 연빨강=휴관) · 이름 · 메타(`지역 · feature · 수심 2m`) · 우측 상태 · 펼침 화살표.
- 종료·휴관 행은 흐리게.
- **펼침(운영/종료 행)**: 그날 슬롯 알약들(오늘이면 끝난 슬롯은 회색) → 요금 3칸(일반·청소년·어린이, 천 단위 콤마) 또는 `priceNote` → `※` 보조 문구(priceNote, 특별 운영 note, pool.note 순) → "자세히 보기 →"(공식 페이지 새 창).
- **펼침(휴관 행)**: 휴관 사유(full 문구) 한 줄.
- 펼침 상태는 수영장별로 기억(탭 이동 후에도 유지, 새로고침 시 초기화).
- 1분마다 다시 계산(오늘 탭에서 "운영중→종료" 전환 반영).

### 5.3 N월 전체보기
- 이번 달과 **다음 달까지만** 이동 가능(범위 끝에서 화살표 비활성).
- 탭을 누르면 항상 이번 달·오늘 선택으로 시작. 월을 옮기면 이번 달=오늘, 다른 달=1일 선택.
- **달력**: 월요일 시작. 날짜 원 색 = 그날 휴관 수 기준 (개장 전·미운영 시설은 계산에서 **제외**)
  - 전부 운영=초록, 전부 휴관=연빨강, 섞임=반반 대각선. 오늘=파란 테두리, 선택일=진한 색.
- **선택일 타임라인**: 제목 `M월 D일 (요일)` + 부제 `N곳 운영 · M곳 휴관`(모두 운영이면 부제 없음. 여기선 미운영도 휴관으로 셈, 개장 전 시설은 제외).
  - 가로축 06~22시, 1시간=40px, 가로 스크롤(이름 칸 고정).
  - 행 = 11곳 고정 순서, 약칭(`POOL_SHORT`). 휴관이면 짧은 사유 문구.
  - 막대 색: 길이 ≤60분 연함 / ≤90분 중간 / 그 이상 진함. 범례 "2시간 이상 · 1시간 30분 · 1시간".

### 5.4 계측 이벤트 (GA4)
`tab_today` / `tab_tomorrow` / `tab_calendar`, 행을 펼칠 때 `pool_<id>`(pool_name 포함).

## 6. 매일 자동 점검 (운영자용)

### 6.1 실행
- 매일 21:00 KST, 맥 launchd → `gh workflow run update-schedule.yml` → 맥 러너에서 실행(최대 120분).
- 수동 실행 입력: `dry_run`(텔레그램·상태 저장 안 함), `only`(정규식에 맞는 글만 다시 읽기), `test_script`(`scripts/test/` 파일 하나만 실행 후 종료).
- 단계 순서:

| # | 단계 | 실패해도 계속? |
|---|------|----------------|
| 1 | 잡 동안 잠자기 방지(caffeinate) | – |
| 2 | 이전 실행 `/tmp` 결과 파일 삭제 | – |
| 3 | 직전 완료 실행 시각 조회 → 누락 일수 계산용 | 예 |
| 4 | `npm ci --prefix scripts` | – |
| 5 | (`test_script`일 때만) 테스트 실행 후 나머지 생략 | – |
| 6 | **시간표 크롤** `check-schedule.js` | 예 |
| 7 | **공지·공휴일 점검** `notice-check.js` | 예 |
| 8 | 금곡 강습 **접수 전날 예고** (→ 스펙-03) | 예 |
| 9 | **텔레그램 발송** `notify-telegram.js` (항상 실행) | 예 |

### 6.2 시간표 크롤 (`check-schedule.js`)
공식 "이용안내" 페이지를 받아 **코드에 박힌 기준값(`KNOWN`, `KNOWN_YOUTH`)**과 비교한다. 기준값은 `index.html`과 수동으로 맞춰 둬야 한다.

| 대상 | 방식 | 비교 항목 | 결과 분류 |
|------|------|-----------|-----------|
| 공사 6곳 | `<h3>일일자유이용…</h3>` 뒤 "수영" `<h5>` 표 (실패 시 "자유수영" 행 폴백) | 휴관주차, 성인 요금(2,000~6,000원), 슬롯(40~130분짜리만) | `changed` |
| 유스센터 3곳(야탑·중원·판교) | "수영장 일일이용" 이후 최대 4,000자 | 휴관주차(숫자/한글 서수), 슬롯 합집합(40~120분) | `youthChanged` |
| 수정유스센터 | 공지 게시판(fmcs/22) + 정식 페이지(fmcs/32) | 근거 공지 존재·제목, 모르는 "수영" 공지 등장, 정식 페이지에 시간표 등장 | `youthChanged` |
| 분당올림픽 | 일일입장안내 페이지 수영 표(평일·토일공휴일 시간, 성인 요금, 정기휴관 주차) 크롤 + 공지 감시 | `KNOWN_KSP` | 변경 시 유스센터 묶음으로 보고 |

- 슬롯 비교: 기준 평일 슬롯 중 사라진 것 + 기준(평일·토·일 전체)에 없는 새 슬롯.
- 페이지의 슬롯은 **평일·주말 구분 없이 한 목록**으로 뽑힌다. 그래서 "어느 요일 시간표가 이렇게 바뀌었다"까지는 알 수 없고, 자동 반영도 하지 않는다(§6.7).
- 슬롯을 하나도 못 뽑으면 "이상 없음"이 아니라 **오류(구조 변경 의심)**.
- 수정유스센터 근거 공지가 게시판 1페이지에 안 보이면, 삭제인지 뒤로 밀린 건지 **상세 페이지를 직접 열어** 제목이 살아 있는지 확인한다(2페이지 목록은 세션 없이 빈 표가 와서 못 씀). 이미 확인한 수영 공지는 `ackNotices`에 등록.
- 요청마다 3회 재시도(15초 타임아웃, 2·4초 간격).
- 종료 코드: `2`=변경 있음, `1`=오류만, `0`=이상 없음. 결과는 `/tmp/schedule-changes.json`, 실행 요약 표(공사 / 유스센터 × 상태)는 GitHub Actions Step Summary에도 남는다.

### 6.3 공지 감시 (`notice-check.js` → `notice-watch.js`)
**제목으로 고르지 않고 모든 게시판의 새 글·수정된 글을 전부 읽는다.** (2026-09에 놓친 휴장이 모두 "재등록 안내"·"강습 안내" 같은 제목 안에 있었음.)

1. **수집** (`notice-sources.js`) — 게시판 하나가 실패해도 나머지는 계속.
   - 공사 6곳: `selectNoticeList.ajax` 첫 페이지 10건(세션 쿠키 먼저 받기). 날짜는 등록일·수정일 중 늦은 것.
   - 분당올림픽: 게시판 목록 1페이지 → 글마다 상세.
   - 유스센터 4곳: 시설별 공지 목록 → 최근 15건 상세. 빈 목록이 오면 3초 뒤 한 번 더.
   - 글 0건이면 "게시판 구조 변경 의심" 오류.
2. **선별** — 글별 해시(제목+본문+첨부명+이미지 수)를 상태 파일에 저장.
   - 처음 보는 글 또는 해시가 바뀐 글(수정됨)만 읽는다.
   - 상태 파일이 없는 첫 실행: 최근 45일 글만 읽고 나머지는 "본 것"으로만 기록.
3. **추출** (`notice-extract.js`, 전부 맥 로컬·무료) — 본문 HTML, PDF(글자 → 없으면 페이지 렌더 후 OCR), HWP(pyhwp), HWPX, 이미지 첨부·본문 이미지(8KB 이상, macOS Vision OCR). 같은 이름의 PDF가 있으면 HWP·이미지는 건너뜀.
4. **운영 관련 필터** — 제목+본문에 휴장·휴관·미운영·운영변경·임시·공사·명절·자유수영·특별운영·단축 등 단어가 없으면 종료(`not-ops`). 제목이 강사 모집·야구장·배드민턴 등 무관 유형이고 수영·휴장 단어가 없으면 종료(`offtopic`).
5. **AI 해석** (`notice-ai.js`, Sonnet 5, 텍스트만 전송) — 구조화 결과:
   - `closures`(휴장 날짜 구간), `openDays`(운영 명시일), `specialSchedules`(기간 한정 시간표·평일/토/일공휴일/매일·대체 여부·성인 요금), `monthlyClosureList`(그 달 휴장일 전체 목록인 글), `unsupported`(지금 구조로 표현 못 하는 변경), `summary`.
   - 강습·행사·정원 변경은 무관 처리. 월간 정규 시간표는 특별 시간표로 넣지 않음. 입력 속 지시문은 따르지 않음.
6. **사이트 대조** (`compareFacts`, 오늘 ~ 120일 뒤) — 사이트 계산(§4)과 비교해 불일치 문장 생성. 날짜는 연속 구간으로 묶어 `10/9(금)~10/11(일)`처럼 쓰고, 구간이 5개 이상이면 `10/1(목) ~ 1/8(금) 중 70일`로 줄인다. 문장 형식은 `<공지 내용> → 사이트는 <사이트 표시>`.
   - 공지=휴장인데 사이트=운영
   - 공지=운영 명시인데 사이트=휴관
   - 월 휴장일 전체 목록 글인데 사이트만 쉬는 날이 있음
   - 특별 시간표가 사이트와 다름(대체면 정확히 일치, 추가면 포함 여부). 사이트가 휴관인 날은 같은 수영장의 **다른 공지들의 휴장일 합집합**에 있으면 모순 아님.
7. **원본 검증** — 불일치가 나온 글만 PDF 페이지·이미지(최대 6장, 장당 4.5MB 이하)를 AI에 보여 주장별 참/거짓 판정. 거짓은 버리고 기록(`rejected`)해 이후 재대조에서도 제외. 검증 호출 실패 시 텍스트 해석대로 알림.
8. **재알림(⏳)** — 예전에 알렸는데 아직 사이트에 반영 안 된 글은 매일 다시 대조해 계속 알림. 사이트를 고치거나 날짜가 지나면 자동으로 사라짐.

**안전장치**
| 장치 | 값 |
|------|-----|
| 실행당 AI 해석 상한 | 20건 (넘는 글은 상태를 안 남겨 다음 날 읽음) |
| 시간 상한 | 45분 |
| 글마다 상태 저장 | 중간에 잘려도 쓴 비용 보존 |
| 키·잔액 오류 | 이번 실행 AI 중단 → "링크만 안내" 무료 모드(같은 글은 한 번만 안내, 키가 돌아오면 다시 해석) |
| 사용액 추정 | 토큰 × 모델 단가(Sonnet 5 입력 $2·출력 $10 / 100만 토큰)로 추정해 `spendUsd`에 누적. `NOTICE_CREDIT_START`(현재 $5) 대비 잔액 $1 이하면 경고. 정확한 금액은 콘솔 기준 |
| 상태 정리 | 게시일 1년 지난 글 기록 삭제 |

상태 파일: 맥 `~/.swim-notice/state.json` (`NOTICE_STATE`로 변경). 맥이 바뀌면 첫 실행처럼 동작.

### 6.4 공휴일 점검
- 매일 data.go.kr 특일정보 API로 **이번 달 + 다음 달**(사이트 달력이 보여 주는 범위)을 조회해 `HOLIDAYS`와 비교한다. 임시공휴일이 급히 지정돼도 API에 올라온 다음 날 밤에 잡힌다.
- `missing`: 공식 공휴일인데 `HOLIDAYS`에 없음 → 🚨 항상 알림.
- `extra`: `HOLIDAYS`에 있는데 공휴일이 아님 → 🚨 항상 알림 (평일이 휴일 시간표로 나오는 사고 방지).
- 매월 1일 다이제스트에는 그 달 공휴일 목록(대체공휴일 포함)을 "확인 필요"로 첨부. (목록 대상 월: 실행일 25일 이후면 다음 달, 아니면 이번 달)
- 한 달이라도 조회에 실패하면 메시지가 나가는 날 `⚠️ 공휴일 조회 실패`로 표시.
- `LUNAR_HOLIDAYS`(설·추석 연휴)는 자동 검사하지 않는다. 설·추석 **대체공휴일**에 공사 수영장이 쉬는지 확인되지 않아, 지금은 "일요일 시간표로 운영"으로 둔다. 공지 감시가 그날 휴장 공지를 잡으면 그때 반영한다.

### 6.5 월말 TO-DO (부가)
- 매월 **말일** 실행에서만, 다음 달 1일용 TO-DO를 **별도 메시지**로 보냄: 구글시트 '변경사항' 탭(CSV)에서 대상월=다음 달인 행 + 끝나는 달 SEO 성과 기록 시트 링크.
- 시트 헤더: 대상월 | 발견일 | 적용일 | 내용 (열 순서 무관, 이름으로 찾음). CSV가 아니면(웹 게시 안 됨) 오류 문구.
- 시트 주소: `SEO_CHANGES_CSV_URL` → 없으면 `data/monthly-todo.json`의 `changesCsvUrl` → 둘 다 없으면 "변경사항 시트 미연동" 문구. SEO 링크는 같은 파일의 `seoDocUrl`.
- 날짜 표기: 발견일≠적용일이면 `(발견 7/18 · 적용 9/1)`, 같으면 하나만.

### 6.6 텔레그램 점검 메시지 (`notify-telegram.js`)
발송 조건: **매월 1일이거나 알릴 것이 있을 때만**. 그 외 날은 조용히 건너뜀. (말일 TO-DO는 별도로 항상.)

메시지 구성 순서:
1. `🏊 성남 수영장 점검 — M/D(요일)`
2. 직전 완료 실행과 48시간 넘게 벌어졌으면 `⚠️ 마지막 점검 이후 N일` 배너
3. `⚠️ 시간표 변경 감지` (공사+유스센터, 수영장별 공식 페이지 링크 + "맞으면 알려주세요" 안내)
4. `📢 새 공지 — 사이트 반영 필요` (수영장·제목·(수정됨)·공지 링크 + 불일치 문장)
5. `🛠 새 구현 필요` (unsupported)
6. `⏳ 이전에 알린 공지 — 아직 사이트 미반영`
7. AI 상태: `💳 크레딧 소진` / `🔑 AI 해석 불가` / `🔑 AI 미사용 모드`
8. `📄 확인할 새 공지 N건` (무료 모드, 최대 12건)
9. `🔎 직접 확인 필요` (해석 실패, 첨부 일부 못 읽음)
10. 잔액 경고, 공지 감시 자체 오류, 다음으로 미룬 건수
11. (1일만) `📅 이 달 공휴일`
12. `🚨 우리 데이터에 빠진 공휴일` / `🚨 공휴일이 아닌데 우리 데이터에 있는 날`
13. (1일 + 알릴 것 없음) `✅ 시간표·공지 이상 없음`
14. `⚠️ 크롤 실패: 수영장(시간표·공지)` — 같은 수영장은 한 번만, 어느 단계인지 표기
15. `⚠️ 공휴일 조회 실패`

**공지 링크**: 공사 공지 상세는 POST로만 열려서 `https://swim.andlife.app/n.html?b=<게시판>&i=<글번호>` 중계 페이지를 쓴다. n.html은 idx를 검증(숫자 1~10자리)한 뒤 폼을 자동 제출하고, 실패 시 게시판 목록 링크를 보여 준다(검색 제외 `noindex`).

### 6.7 변경 반영 흐름
**모든 반영은 사람이 한다.** 점검은 텔레그램으로 알리기만 하고 저장소를 고치지 않는다. (GitHub 이슈 + `/confirm` 댓글 자동 반영은 2026-09-28 폐지 — 슬롯을 요일별로 구분할 수 없어 자동 반영이 평일 시간표를 지울 수 있었고, 실제로 쓰지 않았다.)

| 종류 | 반영 방법 | 알림이 사라지는 때 |
|------|-----------|--------------------|
| 시간표 변경(공사·유스센터) | `index.html`의 `POOLS` **와** `check-schedule.js`의 `KNOWN`/`KNOWN_YOUTH`를 함께 수정 | 기준값이 라이브와 같아지면 |
| 수정유스 새 공지 | 확인 후 `SUJEONG_NOTICE.ackNotices`에 추가(필요하면 index.html 수정) | 다음 날부터 |
| 공지 불일치(📢·⏳) | `index.html`의 `extraClosed*`/`notOperating`/`specialSchedules` 등 수정 | 사이트 계산이 공지와 같아지거나 날짜가 지나면 |
| 공휴일 누락/오입력 | `HOLIDAYS`·`LUNAR_HOLIDAYS` 수정 | 다음 날부터 |

반영하지 않으면 **매일 밤 같은 알림이 반복**된다(잊지 않게 하는 장치). 변경사항 시트 기록이 필요하면 `node scripts/change-log.js "<내용>" --disc M/D --eff M/D`로 직접 남긴다(대상월: 적용월이 미래면 그 달, 아니면 다음 달).

## 8. 알려진 한계·위험 (2026-09-28 코드 기준)

> 점검 중 발견한 것. 스펙 결정이 필요한 항목은 "결정 필요"로 표시.

1. **공휴일은 연 1회 손으로 추가** — 현재 2025~2027년. 매년 6월 말 우주항공청 "다음 해 월력요항"이 나오면 그해 안에 추가한다. 늦어도 12월 달력이 다음 해 1월을 보여 주기 시작하는 **12/1 점검**에서 🚨로 잡힌다.
2. 크롤러 기준값(`KNOWN*`)은 index.html과 **수동 동기화**. 한쪽만 고치면 매일 오탐.
3. 수정유스센터는 매주 일요일 휴관을 `closedWeeks:[1,2,3,4,5]`로 표현해 휴관 사유가 "매월 1·2·3·4·5번째 일요일 정기휴관"으로 보인다.
4. 웹 화면은 방문자 기기 시각을 쓴다. 해외 시간대 기기에서는 "오늘"이 어긋난다.
5. 공사 게시판은 첫 페이지 10건만 본다. 하루에 10건 넘게 올라오면 밀린 글을 놓칠 수 있다(유스센터는 15건).
6. 맥이 24시간 넘게 꺼져 있으면 대기 실행이 취소돼 그날 점검이 통째로 누락된다(복귀 후 "N일" 배너로만 알림). 맥이 완전히 꺼져 있으면 자동 깨우기도 안 된다.
7. 분당올림픽 시간표는 `check-schedule.js`의 `KNOWN_KSP`와 대조한다(2026-10-01 추가). 설 연휴 휴관 여부는 미확인(코드 주석).
8. 푸터의 시설 수·"데이터 기준 2026년 7월", `sitemap.xml`의 `lastmod`는 손으로 고쳐야 한다.
9. **"슬롯 없음"과 "휴관"이 화면마다 다르게 보일 수 있다** — 휴관일이 아닌데 그 요일 슬롯이 빈 배열이면, 목록은 "휴관"(펼치면 엉뚱하게 "정기휴관" 사유)으로, 달력 색은 "운영"으로, 타임라인은 빈 줄로 나온다. 지금 데이터엔 해당 사례가 없지만(수정유스 일요일은 `closedWeeks`로 막음), 요일에 슬롯을 비울 때는 휴관 규칙도 함께 넣어야 한다.
