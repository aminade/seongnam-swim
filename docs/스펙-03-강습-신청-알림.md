# 스펙 03 — 강습 신청 일정 모니터링 (금곡)

> 기준 커밋 `d30cd8c` (2026-09-28). 개요: [스펙-00-개요.md](스펙-00-개요.md)

## 1. 목적

금곡공원국민체육센터가 매달 올리는 강습 공지를 매일 읽어, **운영자가 관심 있는 강좌가 개설됐는지**와 **신규 접수·추첨 신청이 언제인지**를 텔레그램으로 알려준다.
선착순 접수는 시작 시각을 놓치면 끝이므로, **전날 밤·당일 아침·추첨 시작일 저녁**에 맞춰 알린다.

- 사용자: 운영자 본인 1명 (텔레그램 봇 "Today Swim").
- 웹 화면 없음. 사이트 방문자에게는 노출되지 않는다.
- AI·유료 API를 쓰지 않는다(규칙 파싱). 그래서 **메시지에 항상 원본 공지 링크**를 넣어 사람이 확인하게 한다.

### 성공 기준
- 새 달 강습 공지가 올라오면 다음 날 아침 8시에 관심 강좌 개설 여부를 안다.
- 관심 강좌가 있으면 신규 접수 **전날 밤 + 당일 아침**, 추첨 **신청 시작일 저녁**에 알림을 받는다.
- 같은 알림을 두 번 받지 않는다.

### 범위 밖
- 금곡 외 시설, 실제 수강 신청 대행, 어린이 수영·아쿠아로빅·탁구 등 관심 목록 밖 종목, 재등록 알림(재등록 일정은 메시지에 한 줄만).

## 2. 설정 (`data/lesson-watch.json`)

관심 종목·시간이 바뀌면 **이 파일만** 고친다.

```json
{
  "pool": { "id": "geumgok", "name": "금곡공원국민체육센터", "boardUpId": "06" },
  "관심": {
    "수영":     { "아이콘": "🏊", "강좌": ["기초1","기초반","초급2","중급3","중급4"], "시작시각": [6,7,19,20], "비고": "성인만. 어린이수영은 제외" },
    "배드민턴": { "아이콘": "🏸", "강좌": [], "시작시각": [6,7,19,20] }
  },
  "이미등록": []
}
```

| 필드 | 의미 |
|------|------|
| `pool.id` | 어느 공사 게시판을 볼지(`notice-sources.js`의 `SPO_BOARDS`에서 찾음). `boardUpId`·`name`은 참고용(코드 미사용) |
| `관심.수영.강좌` | 관심 반 이름. 공지의 반 이름과 **정확히 같아야** 일치 |
| `관심.*.시작시각` | 관심 시작 시(정수). 강습 시간의 시작 시가 이 목록에 있어야 일치 |
| `관심.배드민턴.강좌` | 비어 있음 — 배드민턴은 반 이름 없이 **시작 시각만** 본다 |
| `비고` | 사람용 메모(코드 미사용). 어린이 제외는 파서가 처리 |
| `이미등록` | 이미 다니는 종목 목록. 비어 있지 않으면 메시지에 재등록 기간 줄을 넣음 |
| 관심 목록 문구 | "미개설" 메시지의 관심 목록은 이 설정에서 자동 생성 |

## 3. 실행 시각과 모드

| 시각 (KST) | 트리거 | 모드 | 보낼 수 있는 알림 |
|------------|--------|------|-------------------|
| 08:00 | 맥 launchd → `lesson-alert.yml -f mode=morning` | `morning` | ① 새 공지, ③ 접수 당일 |
| 19:00 | 맥 launchd → `lesson-alert.yml -f mode=evening` | `evening` | ④ 추첨 신청 시작 |
| 21:00 | 매일 점검 `update-schedule.yml`의 한 단계 | `eve` (`LESSON_MODE=eve`) | ② 접수 전날 |

- 모드는 맥 예약이 넘긴 값(`mode` 입력 → `LESSON_MODE`)을 쓴다. 그래서 맥이 잠들어 08:00 실행이 오후로 밀려도 아침 알림으로 처리된다. 값이 없거나(손으로 실행) 알 수 없는 값이면 KST 12시 전=`morning`, 이후=`evening`.
- 맥은 07:58·18:58·20:58에 자동으로 깨어난다. 잡 동안 잠자기 방지. 실행 제한 30분(강습 워크플로).
- 21:00 단계가 실패해도 매일 점검 전체는 계속된다.

## 4. 처리 흐름 (`scripts/lesson-alert.js`)

1. **게시판 읽기** — 금곡 공사 게시판 첫 페이지(최근 10건).
2. **강습 프로그램 공지 찾기** — 제목에 `강습 프로그램`이 있고 `수강신청`·`추첨제`는 없는 **첫 글**(=최신). 없으면 종료.
3. **대상 월** — 제목의 `N월`(+`YYYY년`). 연도가 없고 N월이 이번 달보다 작으면 내년. 못 읽으면 종료.
4. **수강신청 안내 공지 찾기** — 제목에 `수강신청` 또는 `추첨제`가 있고 같은 `N월`이 들어간 글. 없을 수 있음.
5. **본문·첨부 텍스트 추출** — 공지 감시와 같은 로컬 추출기(PDF·HWP·이미지 OCR). 맥 로컬 도구 필요.
6. **개설 강좌 파싱** (`lesson-parse.js`)
   - 수영: `○ 수영`으로 시작하는 줄 다음부터 다음 `○` 줄 또는 `어린이`가 들어간 줄 전까지. 줄에 `HH:MM~HH:MM`이 있으면 현재 시간으로 잡고, 그 뒤의 반 이름(`기초반`, `기초N`, `초급N`, `중급N`, `상급N`, `고급N`)을 모두 그 시간의 강좌로 기록. → `[{hour, time, course}]`
   - 배드민턴: `○ 배드민턴` 구간의 시간 줄 + 괄호 안 요일. → `[{hour, time, days}]`
7. **관심 대조** — 수영: 반 이름 ∈ `강좌` **그리고** 시작 시 ∈ `시작시각`. 배드민턴: 시작 시 ∈ `시작시각`.
8. **접수 일정 파싱** (수강신청 공지가 있을 때)
   - 접수는 대상 월의 **전달**에 진행된다고 가정.
   - 재등록: 본문에서 처음 나오는 `M/D ~ M/D`.
   - 신규 접수: 처음 나오는 `M/D(요일) H시`.
   - 1차 추첨: `1차 추첨 D일 HH:MM ~ D일 HH:MM D일 HH:MM` → 신청 시작·마감·추첨 발표 (월=전달).
   - 못 읽은 값은 비워 둔다(null).
9. **보낼 알림 결정**(§5) → 발송 → 상태 기록.

## 5. 알림 종류와 조건

| # | 종류(key) | 모드 | 조건 | 관심 강좌 없을 때 |
|---|-----------|------|------|-------------------|
| ① | `new` 새 공지 | morning | 이 달(대상 월)에 아직 안 보냄 | **보냄**(미개설 안내) |
| ② | `signup-eve` 접수 전날 | eve | 내일 = 신규 접수일 | 안 보냄 |
| ③ | `signup` 접수 당일 | morning | 오늘 = 신규 접수일 | 안 보냄 |
| ④ | `lottery` 추첨 시작 | evening | 오늘 = 추첨 신청 시작일 | 안 보냄 |

- **중복 방지**: `대상월:종류`(예 `2026-10:signup`)를 맥 `~/.swim-notice/lesson-state.json`에 기록. 같은 키는 다시 안 보낸다. (`LESSON_STATE`로 경로 변경)
- **지난 달 생략**: ①을 보내려는데 신규 접수일·추첨 마감일이 모두 오늘 이전이면, 보내지 않고 "보낸 것"으로만 기록.
- 새 공지는 오후에 올라와도 **다음 날 아침 8시**에 알린다(① 은 morning 전용).

## 6. 메시지 형식 (텔레그램 HTML)

### 6.1 관심 강좌 있음
```
⭐ 금곡 10월 강습 신청 - 수영, 배드민턴 — 내일 신규 접수
                                          (종류별 꼬리: 내일 신규 접수 / 오늘 신규 접수 / 오늘 추첨 신청 시작 / ①은 없음)

🏊 수영 기초1 (19:00~19:50), 중급3 (20:00~20:50)
🏸 배드민턴 06:00~07:50

추첨 : 신청 9/22(화) 20시~9/27(일) 24시, 추첨 9/28(월) 11시   ← 추첨 대상 강좌가 있을 때
신규 접수 : 9/23(수) 11시                                   ← 선착순 대상 강좌가 있을 때(못 읽으면 "확인 필요")
재등록 : 9/16(수)~9/21(월)                                  ← 이미등록이 있을 때만

10월 강습프로그램 →   (원본 공지 링크)
```
- 수강신청 공지가 아직 없으면 일정 줄 대신 *"수강신청 안내 공지가 아직 안 올라왔어요. 올라오면 일정을 다시 알려드릴게요."*
- **추첨 대상** 판정: 배드민턴 전부, 수영은 반 이름이 `기초`로 시작하는 것. 그 외 수영 반은 선착순. (공지 문구 "성인수영(기초반) 및 배드민턴 … 추첨제" 근거)

### 6.2 관심 강좌 없음 (①만)
```
⭐ 금곡 10월 강습 — 관심 강좌 미개설

관심 목록(수영 기초1·기초반·초급2·중급3·중급4, 배드민턴)에 해당하는 강좌가 이번 달 시간표에 없어요.
10월 강습프로그램 보기
```

### 6.3 링크
공지 링크는 `https://swim.andlife.app/n.html?b=06&i=<글번호>` 중계 페이지(공사 공지 상세가 POST 전용이라서). 스펙-01 §6.6 참고.

## 7. 수동 실행·테스트

| 방법 | 내용 |
|------|------|
| GitHub에서 `lesson-alert.yml` 수동 실행 | `mode`: `morning`/`evening`(비우면 시각으로) / `dry_run`: 텔레그램 대신 로그 출력 / `force`: `new`·`signup-eve`·`signup`·`lottery` 중 하나를 조건 무시하고 발송 |

## 8. 알려진 한계·위험

1. **금곡 한 곳 전용** — `pool.id`만 바꿔도 다른 공사 시설 게시판은 읽지만, 공지 양식(`○ 수영`, `1차 추첨 …` 문구)이 다르면 파싱이 안 된다. 제목 머리("금곡 N월 강습")도 코드에 고정.
2. **양식 의존 파서** — 재등록·신규 접수는 "본문에서 **처음** 나오는" 날짜 패턴을 쓴다. 공지 문구 순서가 바뀌면 엉뚱한 날짜를 잡을 수 있다. 추첨 월은 무조건 대상 월의 전달로 가정.
3. **"다시 알려드릴게요"의 실제 의미** — 수강신청 공지가 나중에 올라와도 즉시 알림은 없다. 관심 강좌가 있을 때 ②③④(전날·당일·추첨 시작) 알림으로만 이어진다. 관심 강좌가 없으면 이후 알림은 없다.
4. **접수 시각 가정** — ③은 08:00에 보내므로 신규 접수가 8시 이전이면 늦다. ②(전날 21시)가 그 대비책. ④는 19:00이라 추첨 신청이 19시 이전에 시작하면 늦는다.
5. **게시판 첫 페이지(10건)만** 본다. 강습 공지가 밀려나면 "강습프로그램 공지 없음"으로 조용히 끝난다(알림 없음).
6. **파서 테스트가 라이브 게시판 의존** — 10월 공지가 게시판 첫 페이지에서 밀려나면 테스트가 깨진다(코드 결함이 아님). 고정 텍스트 픽스처로 바꾸는 것을 검토.
7. **파싱 실패가 조용함** — 대상 월을 못 읽거나 일정이 null이어도 운영자에게 알림이 가지 않는다(로그에만 남음). 신규 접수를 못 읽으면 ②③이 영영 안 온다. (결정 필요: 관심 강좌는 있는데 일정 파싱이 비면 경고를 보낼지)
8. 상태 파일이 맥에만 있어 맥을 바꾸면 이번 달 알림이 다시 올 수 있다.
9. 실행이 밀리면 알림도 늦게 간다 — 모드는 유지되지만(2026-09-28 수정), 예를 들어 ③ 접수 당일 알림이 접수 시각 뒤에 도착할 수 있다. 늦었다는 별도 문구는 붙이지 않는다(결정).
10. 맥이 24시간 넘게 꺼져 있으면 대기 실행이 취소돼 그 회차 알림은 없다.
